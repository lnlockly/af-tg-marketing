# Dressing (Одёжка) — превращаем купленный аккаунт в живого человека

> 🔴 **@username ОБЯЗАТЕЛЕН.** Одёжка без ника — не одёжка. `account_dress` и
> `fleet_dress` **по умолчанию** сами подбирают свободный @username (транслит имени +
> персона → перебор кандидатов) и делают созданный канал **публичным**. Полный «одетый»
> аккаунт = имя + био + **несколько фото** + **@username** + свой публичный канал.
>
> 🔴 **РАЗДЕЛЕНИЕ ТРУДА ПО ФОТО (важно — так работает агент).** Наш `leads-ops` MCP фото
> НЕ ищет и НЕ генерит — он их только **ставит**. **Источник фото — ТЫ сам, своими
> НАТИВНЫМИ тулами:**
> - синтетические лица → твоя нативная `image_generate` (gpt-image-2);
> - фото из интернета → твоя нативная image-search / браузер-тула;
> - фото юзера → он сам их прислал (скачай через нативную тулу).
>
> Затем передаёшь **готовые файлы** в `account_dress(photos="/path/a.jpg,/path/b.jpg")`
> (или папку) — он поставит их ГАЛЕРЕЕЙ (несколько = реалистично). Для флота клади файлы
> в `photos_dir/<account_id>/` и зови `fleet_dress(photos_dir=...)`.
>
> ⚠️ **Безопасность:** только свои фото юзера / синтетика (AI) / нейтральный сток.
> **НИКОГДА не бери фото конкретного реального человека** — это выдача себя за другого.
> Пустой numeric-username `user1837462` = палево, так не оставляем.

## Зачем это вообще нужно

Купленный Telegram-аккаунт по умолчанию — это пустышка: numeric-username вроде
`user1837462`, без фото, без био, без единого сообщения в профиле, без своего
канала. Такой профиль кричит «я бот/спам-аккаунт» ещё до первого сообщения. Когда
цель получит первое письмо и ткнёт в профиль отправителя — она за 2 секунды
решает «человек или мусор». Если профиль пустой — репорт, а не ответ. Репорты
убивают аккаунт (и деньги, потраченные на его покупку и прогрев).

**Одёжка — это второй шаг воронки, сразу после `account_ingest` и ДО прогрева.**
Порядок жёсткий:

```
buy account+proxy → account_ingest → [ОДЁЖКА: account_dress / fleet_dress]
  → warmup_control start (ждём ДНИ) → campaign_create → ...
```

Одеваем **до** прогрева, потому что прогрев уже симулирует активность живого
человека — а у живого человека к моменту, когда он начинает переписываться, УЖЕ
есть фото, имя и, часто, свой канал. Одеть после прогрева — логическая дыра в
легенде (аккаунт «жил» неделю безликим, потом внезапно оброс лицом).

Одёжка НЕ трогает устройство и прокси — это зафиксировано на `account_ingest`
(desktop-fingerprint под app_id 2040, прокси страны аккаунта). Одёжка — это то,
что видит человек: **имя, био, аватар, свой канал**.

## Инструменты

Одёжкой управляют ровно два инструмента leads-ops MCP:

- **`account_dress(account_id, persona, ai?, avatar_ai?, with_channel?, ...)`** —
  одеть ОДИН аккаунт. Точный контроль над конкретной персоной.
- **`fleet_dress(ids|all, persona_pool?, avatar_ai?, with_channel?)`** — одеть
  ПАЧКУ аккаунтов из пула персон. Для флота одинаковой аудитории.

Вспомогательное: `account_list(active_only?)` — увидеть, какие аккаунты уже
влиты и в каком они состоянии (одеты / голые / прогреты).

### Параметры и что они делают

| Параметр | Что делает |
|----------|-----------|
| `account_id` | какой аккаунт одеваем (из `account_list`) |
| `persona` | легенда человека: имя, фамилия, био, интересы, «кто он». Основа всего |
| `ai` (true) | сгенерировать имя+фамилию+био нейросетью из persona-брифа, а не брать буквально |
| `avatar_ai` (true) | сгенерировать аватар через **gpt-image-2** под persona (лицо/стиль) |
| `with_channel` (true) | создать аккаунту СВОЙ публичный канал и привязать (реальный признак живого) |
| `persona_pool` (fleet) | набор персон/брифов, из которого fleet_dress раздаёт разные легенды на каждый аккаунт |

## Дизайн персоны — сердце одёжки

Аватар и канал бесполезны, если персона не бьётся с аудиторией кампании.
**Правило когерентности: персона должна выглядеть как "свой" для той аудитории,
которую мы будем писать.** Человек отвечает тем, кто похож на него/на «своих».

### Шаг 1. Оттолкнись от аудитории кампании

Перед тем как одевать, ответь себе: **кому** этот аккаунт будет писать
(`audience` будущей кампании) и **что** продаём (`product`)?

Персона — это НЕ случайный человек. Это правдоподобный участник той же среды.

**Примеры когерентности:**

- Аудитория: мамы в чатах о раннем развитии. Продукт: детский центр.
  → Персона: женщина 28–36, имя из региона аудитории, био «мама двоих, Москва,
  делюсь находками для детей», аватар — женское лицо, тёплый бытовой фон. Канал:
  «Записки мамы» с 3–5 постами про детский досуг.
  ✗ ПЛОХО: мужчина-«инвестор» 45 с био про крипту — чужой, инстант-репорт.

- Аудитория: предприниматели в чатах по маркетингу. Продукт: услуга трафика.
  → Персона: 25–35, «делаю перформанс для локального бизнеса», аватар —
  нейтральный портрет в деловом-casual, канал с 2–3 кейсами.
  ✗ ПЛОХО: аниме-аватар и био «люблю котиков» — не читается как коллега.

### Шаг 2. Собери persona-бриф

Хороший бриф для `persona` содержит:

- **Пол и возрастная вилка** (влияет на имя, аватар, тон). Помни: первое
  сообщение кампании всё равно гендерно-нейтральное к получателю, но САМ
  отправитель имеет пол — и он должен читаться консистентно везде.
- **Регион/язык** — совпадает с аудиторией и, в идеале, со страной аккаунта.
  RU-аудитория → русское имя, русское био.
- **Занятие/роль** — «свой» для среды (мама, коллега-предприниматель, участник
  хобби-комьюнити).
- **1–2 живые детали** — город, «двое детей», «варю кофе», «бегаю по утрам».
  Детали делают профиль человеческим и дают крючки для small talk в диалоге.
- **Тон** — как он пишет (тёплый / деловой / свойский). Это же согласуется с
  `reply_prompt` кампании.

Пример вызова:

```
account_dress(
  account_id="acc_7731",
  persona="Женщина 31 год, Казань. Мама сына 4 лет. Ушла из офиса, ведёт быт и
           ищет занятия для ребёнка. Тёплая, простая речь, без канцелярита.
           Интересы: детский досуг, развивашки, семейные выходные.",
  ai=true,            # сгенерить имя/фамилию/био из брифа
  avatar_ai=true,     # аватар gpt-image-2 под эту персону
  with_channel=true   # свой канал «мамских» заметок
)
```

С `ai=true` движок сам произведёт правдоподобные **имя+фамилию** (Алина
Сафина, а не «Женщина 31») и человеческое **био** из брифа — не копируй бриф
буквально в имя.

## Аватар (avatar_ai → gpt-image-2)

Аватар генерится нейросетью **gpt-image-2** под персону. Что делает хороший
аватар:

- **Одно узнаваемое лицо**, соответствующее полу/возрасту/региону персоны.
- **Бытовой, не студийный** фон — «живое» фото, а не сток. Идеальный стоковый
  портрет читается как фейк так же, как пустой профиль.
- **Стабилен на всю жизнь аккаунта.** Как и device-fingerprint — аватар не
  крутим. Живые люди не меняют лицо каждую неделю. Сгенерили один раз при
  одёжке — оставили.
- **Разные лица на разных аккаунтах флота.** Если `fleet_dress` раздаст одно и
  то же лицо десяти аккаунтам — это спам-паттерн, который вычисляется мгновенно.
  Пул персон должен давать РАЗНЫЕ лица.

Плохой аватар: логотип/товар вместо лица (продающий аккаунт, не человек),
знаменитость (reverse-image спалит), пустое место (никакой одёжки).

Если `avatar_ai` недоступен/выключен на поде — это НЕ повод пускать кампанию с
голым профилем. Честно скажи владельцу «аватар-генератор недоступен, аккаунт
без лица = высокий риск репорта» и не запускай рассылку до фикса.

## Свой канал (with_channel)

Ключевой, часто забываемый признак **живого** аккаунта: у реального человека
нередко есть СВОЙ маленький канал (заметки, работа, хобби). Пустой аккаунт без
единого следа присутствия — подозрителен; аккаунт со своим тематическим каналом
на 3–7 постов выглядит настоящим.

`with_channel=true` создаёт аккаунту публичный канал и привязывает его. Канал
должен быть **когерентен персоне**:

- Мама-персона → канал «Наши будни» / «Что делаем с сыном» с бытовыми постами.
- Маркетолог-персона → канал с 2–3 мини-кейсами.

Что делает канал хорошим:
- **Тема = персона = аудитория.** Один смысловой мир.
- **Немного постов (3–7), с разными датами** — не 10 постов за одну минуту.
- **Не продающий в лоб.** Канал — это декорация «я живу», а не витрина товара.
  Продаём в диалоге, не в канале-приманке.

## fleet_dress — одеваем флот

Когда аккаунтов несколько (а для внутреннего прогрева их нужно **2+**), одевай
пачкой через `fleet_dress` с **пулом персон**:

```
fleet_dress(
  ids="all",                # или список конкретных account_id
  persona_pool=[
    "Мама 31, Казань, сын 4 года, тёплая речь ...",
    "Мама 27, Уфа, двойняшки, ищет развивашки ...",
    "Женщина 35, Самара, старшая в школе, младшая в саду ..."
  ],
  avatar_ai=true,
  with_channel=true
)
```

Правила флота:

- **Разнообразие внутри одной аудитории.** Все персоны из пула — «свои» для той
  же среды (мамы), но РАЗНЫЕ: разные города, имена, лица, детали. Однообразный
  флот-клон = паттерн, который банят пачкой.
- **Никаких двух одинаковых аватаров/имён/каналов.** Пул должен быть достаточно
  богатым, чтобы каждый аккаунт получил уникальную легенду.
- **Согласованность с будущей кампанией.** Пул проектируется под конкретную
  `audience`, а не «вообще люди».

## Хорошая vs плохая одёжка — чек-лист

**Хорошая одёжка (аккаунт проходит проверку взглядом):**
- Человеческое имя+фамилия, а не username-цифры.
- Живое био с 1–2 конкретными деталями, без рекламы.
- Аватар — одно бытовое лицо под персону, стабильное.
- Свой тематический канал на 3–7 постов, с разными датами.
- Всё когерентно: пол/возраст/регион/тема канала бьются с аудиторией кампании.
- В рамках флота — все легенды разные.

**Плохая одёжка (инстант-репорт):**
- Пустой профиль или дефолтный username.
- Аватар = логотип/товар/знаменитость/сток.
- Био продаёт в лоб («Пишите в ЛС, скидки!»).
- Персона чужая для аудитории (инвестор в мамском чате).
- Нет своего канала (нет следа присутствия).
- Флот-клоны: одно лицо/имя/канал на многих.

## Как встроить в общий поток (нюансы порядка)

1. **Сначала `account_ingest`** — там уже прибиты desktop-device (app_id 2040,
   никогда не ротируем) и прокси страны аккаунта. Одёжка это НЕ меняет.
2. **Потом одёжка** (`account_dress`/`fleet_dress`) — имя, био, аватар, канал.
3. **Проверь `account_list`** — убедись, что аккаунты помечены как одетые.
4. **Только теперь `warmup_control start`** — прогрев симулирует жизнь УЖЕ
   одетого человека, дни, ~25 действий до «ready». Для внутренних прогрев-DM
   нужно **2+ одетых** аккаунта.
5. Одёжку НЕ запускают на аккаунте, который уже в активной кампании — сначала
   `campaign_control pause` при необходимости.

## Честность с владельцем (safety)

Userbot-флот — серая зона (ToS Telegram). Хорошая одёжка снижает риск репорта,
но НЕ делает аккаунт неубиваемым. Всегда:

- Честно скажи, что одёжка сделана и что осталось (например, «канал создан,
  постов пока 3 — добавить ещё?»).
- Если что-то из одёжки не удалось (нет аватара, канал не создался) — скажи и
  НЕ выдавай аккаунт в кампанию с дырой в легенде.
- Напомни про легальную альтернативу для входящих: **Telegram Business**
  (inbound-only, без Premium) — там одёжка не нужна, потому что человек пишет
  сам.
